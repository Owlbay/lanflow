# 规则、覆写、DNS、嗅探、网络信息（草案）

结论：**都可以实现**，不依赖额外组件。Mihomo 提供了所需的接口，其余由澜流的「配置合成」完成。下面给出精简做法，原则不变：默认不打扰，需要时才展开。

参考：Mihomo 内核的配置项与 REST 接口 `hub/route`（已逐项核对）。

## 0. 共同基础：配置合成

Mihomo 的 `PATCH /configs` 只能即时修改端口、模式、TUN、局域网、日志级别、IPv6、嗅探总开关等少数字段。**DNS 细项、嗅探细项、规则都必须重新生成配置并热重载**。因此五项功能共用一条合成流水线：

```text
订阅原文
  → ① 订阅覆写（YAML，仅作用于该订阅）
  → ② 全局覆写（YAML，作用于所有订阅）
  → ③ 澜流接管项：DNS（如接管）、嗅探（如接管）、自定义规则（插到最前）
  → ④ 澜流托管字段：端口、控制接口、探测监听端口（始终最后写入，不可被覆盖）
  → mihomo -t 校验 → 写入运行时配置 → PUT /configs?force=true 热重载
```

- 任一步失败都保留上一份可用配置，并在界面指出是哪一层出错。
- 提供「查看运行时配置」（只读 YAML），每段标注来源层，方便排查「为什么这样」。

## 1. 规则

| 功能 | 做法 | 优先级 |
| --- | --- | --- |
| 规则列表 | `GET /rules`：序号、类型、内容、目标策略、规则集大小 | P1 |
| 命中统计 | 同一接口返回 `hitCount`、`hitAt`、`missCount`；列表可按命中次数排序，看出哪些规则真正起作用 | P1 |
| 临时停用 | `PATCH /rules/disable`；仅本次运行有效，重载后恢复，界面标注「临时」 | P2 |
| 自定义规则 | 澜流保存一组用户规则，合成时插到订阅规则最前面；类型只开放常用的：域名后缀、域名关键字、完整域名、IP 段、进程名；目标为代理组 / 直连 / 拒绝 | P1 |
| 从连接添加 | 连接页右键：「此域名始终走…」「此程序始终走…」，生成一条自定义规则 | P1 |
| 规则集 | `GET/PUT /providers/rules`：列出 rule-providers、更新时间、条目数，可单独更新 | P2 |
| 规则测试 | 输入域名或 IP，显示会命中哪条规则、走哪个出口 | P3（见下方说明） |

**规则测试的限制**：Mihomo 没有「只匹配不连接」的接口。可选做法：(a) 经内核发起一次真实请求，从 `/connections` 读取命中规则，简单但会产生真实流量；(b) 在澜流内实现常用规则类型的匹配器，但 GEOSITE、GEOIP 需要读取规则数据库，工作量大；(c) 直接引用 Mihomo 的 Go 包实现匹配，但这会使澜流以 GPL-3.0 分发。建议先用 (a)，并在界面上注明会发起一次请求。

## 2. 覆写

| 功能 | 做法 | 优先级 |
| --- | --- | --- |
| YAML 覆写 | 全局一份 + 每个订阅可选一份；深度合并，支持三种写法：`rules` 整体替换、`+rules` 插到前面、`rules+` 追加到后面 | P2 |
| 编辑与校验 | 等宽编辑器（MyGo `CodeEditor`）；保存前做一次完整合成和 `mihomo -t`，失败时显示错误行 | P2 |
| 合成预览 | 保存前显示合成结果与当前运行配置的差异（MyGo `DiffViewer`） | P2 |
| JS 脚本覆写 | 不做。需要内置 JS 引擎（如 goja），带来安全和维护成本；绝大多数需求用 YAML 覆写和自定义规则即可满足 | — |

## 3. DNS

DNS 分两种状态：**跟随订阅**（默认）和**由澜流接管**。接管时，澜流的设置整体替换订阅中的 `dns` 段；跟随订阅时，表单只读显示订阅中的值。

| 设置 | 控件 | 优先级 |
| --- | --- | --- |
| 跟随订阅 / 由澜流接管 | 分段控件；接管时提供「使用推荐设置」一键填入 | P2 |
| 模式 | Fake-IP / 真实 IP（redir-host） | P2 |
| 上游服务器 | `nameserver`，每行一个，支持 DoH / DoT / UDP | P2 |
| 节点域名解析 | `proxy-server-nameserver`：用于解析节点服务器地址 | P2 |
| 直连域名解析 | `direct-nameserver` | P2 |
| 按域名指定服务器 | `nameserver-policy`：两列表格（域名或规则集 → 服务器） | P2 |
| Fake-IP 排除 | `fake-ip-filter`：每行一个域名 | P2 |
| 遵循规则 | `respect-rules`：DNS 请求也按分流规则走 | P2 |
| Hosts | 自定义 hosts 表格 + 「使用系统 hosts」开关 | P2 |
| 工具：DNS 查询 | `GET /dns/query?name=&type=`，显示内核实际解析结果 | P1 |
| 工具：清除缓存 | 「清除 DNS 缓存」`POST /cache/dns/flush`、「清除 Fake-IP 缓存」`POST /cache/fakeip/flush` | P1 |

不提供 `fallback`、`fallback-filter` 等已不推荐使用的旧字段；订阅中如有这些字段，跟随订阅时原样保留。

## 4. 嗅探

同样分为**跟随订阅**和**由澜流接管**。总开关可即时生效（`PATCH /configs` 的 `sniffing`），细项需要重载。

| 设置 | 控件 | 优先级 |
| --- | --- | --- |
| 启用嗅探 | 开关（即时生效） | P1 |
| 跟随订阅 / 由澜流接管 | 分段控件 | P2 |
| 协议与端口 | HTTP（80, 8080）、TLS（443）、QUIC（443）三行，各带开关和端口 | P2 |
| 用嗅探结果覆盖目标地址 | `override-destination` 开关 | P2 |
| 强制嗅探的域名 / 跳过的域名 / 跳过的目标地址 | 三个列表 | P2 |
| 嗅探纯 IP 连接 | `parse-pure-ip` 开关 | P2 |

## 5. 网络信息

尽量用已有的数据源，不引入第三方 IP 查询服务：IP 由 Cloudflare trace 得到（与出口地图共用），位置和运营商由 Mihomo 自带的 GeoIP、ASN 数据库在本机离线查询。

| 区块 | 内容 | 来源 | 优先级 |
| --- | --- | --- | --- |
| 本机直连 | 公网 IP、国家/城市、运营商（ASN） | 经 DIRECT 请求 trace + 本机库 | P1 |
| 代理出口 | 当前出口的 IP、位置、运营商、Cloudflare 机房、「中转」标签 | 与出口地图共用（见 exit-map.md 4A） | P1 |
| 本机网络 | 网络接口、局域网 IP、网关、系统 DNS、当前 Wi-Fi 名称 | 系统 API | P1 |
| 代理状态 | 系统代理是否指向澜流、监听端口、TUN 状态 | 本地 | P1 |
| 网站连通性 | 一组常用网站（Google、YouTube、GitHub、OpenAI 等，可自定义）分别经代理和直连测试延迟 | 经内核和直连各发起一次 HEAD 请求 | P1 |
| 泄漏检查 | DNS 是否经代理、IPv6 是否绕过代理 | 对比直连与代理下的解析和出口 | P2 |
| 流媒体 / AI 解锁检测 | 各服务在当前出口是否可用、所在地区 | 各服务的检测方法经常失效，维护成本高 | 不做 |

## 5A. 外部资源（地理数据库）

规则中的 `GEOIP`、`GEOSITE`、`IP-ASN` 需要查询本地数据库，Mihomo 默认从 MetaCubeX/meta-rules-dat 下载（已核对 `config/config.go` 中的默认值）。

| 项 | 作用 | Mihomo 配置 |
| --- | --- | --- |
| GeoIP 数据库（geoip.dat / geoip-lite.dat） | IP → 国家，DAT 格式；仅在 GEOIP 使用 DAT 时生效。lite 版体积更小 | `geox-url.geoip` |
| GeoSite 数据库（geosite.dat） | 域名分类（cn、google、youtube、category-ads-all 等），GEOSITE 规则必需 | `geox-url.geosite` |
| MMDB 数据库（geoip.metadb） | IP → 国家，MaxMind 格式；默认用于 GEOIP 规则 | `geox-url.mmdb` |
| ASN 数据库（GeoLite2-ASN.mmdb） | IP → 自治系统号和运营商；用于 IP-ASN 规则，澜流的网络页和中转检测也用它 | `geox-url.asn` |
| GeoData 数据模式（db / dat） | GEOIP 规则查 MMDB（db，默认）还是 geoip.dat（dat） | `geodata-mode: false / true` |
| 自动更新 | 内核按间隔重新下载，默认关闭、间隔 24 小时 | `geo-auto-update`、`geo-update-interval` |
| 立即更新 | 不重启内核即可更新 | `POST /configs/geo` |

澜流的做法：应用内置一份初始数据库，首次启动不依赖 GitHub；地址默认不改，放在「设置 › 内核 › 外部资源」；「立即更新」为 P1，其余为 P2。GeoLite2-ASN 来自 MaxMind，随包分发时需按其许可证注明出处。

## 6. 放在哪里（信息架构建议）

```text
侧边栏
  概览 · 代理 · 订阅 · 连接 · 日志
  ───────────────
  规则          ← 新增：规则列表、命中统计、自定义规则、规则集
  网络          ← 新增：网络信息、网站连通性、DNS 查询工具
  ───────────────
  设置
    常规 / 代理 / DNS / 嗅探 / 覆写 / 内核 / 数据   ← DNS、嗅探、覆写放进设置
```

- 规则和网络是「查看」类，单独成页；DNS、嗅探、覆写是「配置」类，放进设置，沿用分组列表样式。
- 订阅页「⋯」菜单增加「编辑覆写」，直接打开该订阅的覆写。
- 侧边栏从 6 项增加到 8 项。
